# Phase 5 — SFTP : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Depuis un onglet SSH, ouvrir un panneau de fichiers sur le même serveur, sans nouvelle authentification.
- Le panneau suit le dossier courant du shell.
- On y navigue, crée, renomme, supprime et change les permissions.
- On transfère dans les deux sens, avec progression, vitesse, annulation et reprise.
- On modifie un fichier dans son éditeur, avec renvoi automatique sur le serveur.

**Architecture:**
- **Côté Rust** (`tilde-ssh`) :
  - `SftpClient` ouvre le sous-système `sftp` sur la connexion existante de la session (`russh-sftp` sur `channel.into_stream()`). Il est rouvert après une reconnexion.
  - `TransferQueue` exécute les transferts en streaming : concurrence configurable, reprise par offset, progression limitée à environ 10 événements par seconde.
  - `EditSession` télécharge un fichier dans un dossier temporaire par session, le surveille (`notify`) et le renvoie après un debounce, sans écraser une version distante modifiée entre-temps.
- **Côté Tauri** : commandes `sftp_*` / `transfer_*` et événements `sftp://transfer`. Les dialogues de fichiers sont ouverts depuis Rust.
- **Côté front** : un panneau `sftp` dans l'arbre de layout, lié à un panneau SSH, et une file de transferts visible depuis la barre de titre.

**Tech Stack:** russh-sftp 3, tokio, notify (déjà là via tilde-config), tauri-plugin-opener / dialog, React, Zustand.

**Spec:** `docs/superpowers/specs/2026-10-23-tilde-design.md` (§4.3, §4.6, §6 phase 5, §7). Plans précédents : phases 1 à 4.

## Global Constraints

- Tout ce qui précède reste valable (crates métier sans Tauri, aucun secret sur disque ni dans les logs, commits conventionnels + `Co-Authored-By`, clippy pedantic `-D warnings`, textes en français).
- Session SFTP ouverte **à la demande** sur la connexion SSH existante : pas de seconde authentification.
- Suivi du cwd par OSC 7 émis par le shell distant. Sans OSC 7, le panneau reste sur `$HOME` et propose un snippet pour `.bashrc` / `.zshrc`. Le suivi peut être lié ou détaché.
- File de transferts côté Rust : concurrence `settings.sftp.concurrency` (défaut **3**, 1 à 16), progression, vitesse, annulation. **Reprise** en comparant les tailles distante et locale, puis écriture avec un offset. Événements de progression ≤ **10/s** par transfert.
- Suppression : confirmation, récursive pour les dossiers. chmod : dialogue octal + cases à cocher.
- Édition externe : téléchargement dans un dossier temporaire **par session**, surveillance `notify`, ré-upload après debounce, statut visible dans la file. Éditeur : `settings.sftp.externalEditor` (commande) sinon l'application par défaut de l'OS.
- Transferts en **streaming** par blocs (256 Kio) : la mémoire ne dépend jamais de la taille du fichier.
- Un nom distant ne peut **jamais** faire écrire en dehors du dossier local choisi (`..`, séparateurs, noms réservés Windows, caractères interdits).

## Review Focus

1. **Noms distants hostiles** (`../x`, `a/b`, `a\b`, `CON`, `nul.txt`, `x:y`, `?`, nom de 300 caractères, fin en espace ou en point) → téléchargés sous un nom sûr, toujours dans le dossier choisi. Test : Task 1 `remote_names_never_escape_the_destination`.
2. **Coupure pendant un transfert** → le transfert passe en échec avec un message clair. « Réessayer » reprend à l'offset, et la session SFTP se rouvre après une reconnexion. Tests : Task 2 `download_resumes_from_a_partial_file`, `upload_resumes_from_a_partial_remote_file`, Task 3 `sftp_reopens_after_reconnect`.
3. **Suppression récursive d'un dossier contenant des liens symboliques** → on supprime les liens, jamais leur cible ni rien hors de l'arbre. Test : Task 1 `recursive_remove_does_not_follow_symlinks`.
4. **Un `cat` géant dans le shell pendant un téléchargement** → le transfert avance et se termine, et le shell reste fluide. Test : Task 2 `shell_flood_does_not_stall_a_transfer`.
5. **Le fichier distant change pendant qu'on l'édite localement** → pas d'écrasement silencieux : statut « conflit », avec le choix d'écraser ou de télécharger la version distante. Test : Task 4 `edit_detects_a_remote_change_before_uploading`.

### Task 1 : `tilde-ssh` — client SFTP

**Files:**
- Create: `crates/tilde-ssh/src/sftp.rs`, `crates/tilde-ssh/tests/sftp.rs` (`integration`)
- Modify: `crates/tilde-ssh/Cargo.toml` (`russh-sftp = "3"`), `src/lib.rs`

**Interfaces:**
- Produces :
  - `pub enum EntryKind { File, Dir, Symlink, Other }` (Serialize camelCase).
  - `pub struct RemoteEntry { name: String, path: String, kind: EntryKind, size: u64, modified: Option<u64> /* s Unix */, permissions: Option<u32> }`.
  - `pub struct SftpClient` :
    - `open(connection: &Connection) -> Result<Self, SftpError>` (`channel_open_session` + `request_subsystem(true, "sftp")` + `SftpSession::new(channel.into_stream())`, borné par un délai de 15 s) ;
    - `home() -> Result<String>` (`canonicalize(".")`) ;
    - `list(path) -> Result<Vec<RemoteEntry>>` : dossiers d'abord, puis tri par nom insensible à la casse ; `.` et `..` exclus ;
    - `stat(path) -> Result<RemoteEntry>` ;
    - `mkdir(path)`, `rename(from, to)` ;
    - `remove(path) -> Result<u64>` : récursif, renvoie le nombre d'éléments supprimés, n'entre jamais dans un lien symbolique (`symlink_metadata`), plafond `MAX_REMOVE = 100_000` ;
    - `chmod(path, mode: u32)` (les 12 bits bas seulement) ;
    - `inner() -> &SftpSession` (pour la file).
  - `pub enum SftpError { Unavailable(String), Io { path: String, message: String }, TooMany }` (Display en français, avec le chemin).
  - `pub fn safe_local_name(remote: &str) -> String` :
    - garde le dernier segment après `/` et `\` ;
    - remplace `< > : " | ? *` et les caractères de contrôle par `_`, et retire les points et espaces finaux ;
    - préfixe `_` un nom réservé Windows (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`, insensible à la casse et à l'extension) ;
    - tronque à 200 octets UTF-8 en gardant l'extension ; `""`, `.` ou `..` donnent `fichier`.
  - `pub fn join_remote(dir, name) -> String` (POSIX, sans double `/`).

### Task 2 : File de transferts (reprise, annulation, progression)

**Files:**
- Create: `crates/tilde-ssh/src/transfer.rs`, `crates/tilde-ssh/tests/transfer.rs` (`integration`)

**Interfaces:**
- Consumes : Task 1 `SftpClient`, `safe_local_name`, `join_remote`.
- Produces :
  - `pub enum Direction { Upload, Download }`.
  - `pub enum TransferState { Queued, Running, Done, Failed { message: String }, Cancelled }`, plus pour l'édition `Conflict { message: String }`.
  - `pub struct TransferInfo { id: u32, direction, local: String, remote: String, total: u64, done: u64, bytes_per_sec: u64, state, session: u32 }` (Serialize camelCase).
  - `pub struct TransferQueue` :
    - `new(concurrency: usize, on_event: Arc<dyn Fn(TransferInfo) + Send + Sync>)` ;
    - `set_concurrency(n)` ;
    - `download(session, client: Arc<SftpClient>, remote, local_dir) -> u32` : un dossier est parcouru récursivement en un transfert par fichier, avec des noms locaux passés par `safe_local_name` ;
    - `upload(session, client, local, remote_dir) -> u32` : un dossier local donne l'arborescence correspondante ;
    - `cancel(id)` ; `retry(id, client)` (reprend à l'offset) ; `list() -> Vec<TransferInfo>` ; `cancel_session(session)` ; `clear_finished()`.
  - Reprise :
    - au téléchargement : un fichier local existant plus court que le distant → reprise depuis sa taille, le distant étant lu avec `seek` ;
    - plus long ou égal mais différent → réécrit ;
    - à l'envoi, même logique avec la taille distante.
    Les données passent d'abord par un fichier `.part` local, renommé à la fin du téléchargement.
  - Vitesse : moyenne glissante sur environ 2 s. Événements : au plus un toutes les 100 ms par transfert, plus un à chaque changement d'état.
- [ ] **Step 1 : Tests**
  - Unitaires : `progress_events_are_throttled` (un `Throttle` pur) et `speed_is_a_moving_average`.
  - Intégration :
    - `upload_then_download_round_trips` (fichier de 5 Mo, octets identiques) ;
    - `download_resumes_from_a_partial_file` (un `.part` de 1 Mo laissé en place, octets lus ensuite au plus ~4 Mo + 1 bloc) ;
    - `upload_resumes_from_a_partial_remote_file` ;
    - `cancel_stops_and_keeps_the_part_file` ;
    - `concurrency_is_respected` (5 transferts, au plus 2 en `Running` à la fois avec `new(2, …)`) ;
    - `directories_transfer_recursively` ;
    - `shell_flood_does_not_stall_a_transfer` (shell `yes | head -c 200000000` sans ack pendant le téléchargement de 20 Mo, terminé en moins de 20 s).
- [ ] **Step 2 → 4 :** RED, implémentation, GREEN.

### Task 4 : Édition externe

**Files:**
- Create: `crates/tilde-ssh/src/edit.rs`, tests unitaires dans le module + `crates/tilde-ssh/tests/edit.rs` (`integration`)
- Modify: `crates/tilde-ssh/Cargo.toml` (`notify`, `notify-debouncer-full`, mêmes versions que `tilde-config`)

**Interfaces:**
- Produces :
  - `pub struct EditSession` :
    - `start(root: PathBuf /* dossier temporaire de la session */, client, remote: String, open: impl Fn(&Path)) -> Result<Self>` : télécharge dans `root/<hachage du chemin distant>/<safe_local_name>`, retient la taille et la mtime distantes, ouvre le fichier puis le surveille ;
    - à chaque modification locale stabilisée (debounce **500 ms**) : `stat` distant. Si la taille ou la mtime a changé depuis le dernier téléchargement ou envoi → `Conflict`, sans envoi. Sinon → envoi, et les nouvelles taille et mtime sont retenues ;
    - `resolve(overwrite: bool)` : `true` envoie quand même, `false` retélécharge ;
    - `stop()` : arrête la surveillance.
  - L'état est publié comme un `TransferInfo` (direction `Upload`, `local` = fichier temporaire) pour apparaître dans la file.
  - `pub fn session_temp_dir(session: u32) -> PathBuf` (`dirs::cache_dir()/Tilde/edit/<pid>-<session>`), supprimé à la fermeture de la session ; les dossiers orphelins de plus de 7 jours sont nettoyés au démarrage.
- [ ] **Step 1 : Tests**
  - Unitaires (sans réseau, avec un `RemoteFile` simulé derrière un trait interne) : `edit_uploads_after_debounce` (deux écritures rapprochées donnent un seul envoi, avec le dernier contenu) et `edit_detects_a_remote_change_before_uploading`.
  - Intégration : `edit_round_trip` (modifier le fichier local, puis le contenu distant est mis à jour).
