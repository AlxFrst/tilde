# Phase 3 — SSH : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ouvrir un shell SSH dans un onglet Tilde à partir d'un alias de `~/.ssh/config` (ou de `user@host:port`), du premier coup, y compris derrière plusieurs bastions, avec vérification `known_hosts`, agent, clés à passphrase, keepalive, reconnexion et tunnels, et des erreurs qui disent pourquoi.

**Architecture:** Trois briques sans Tauri.
- `tilde-ssh-config` : parser pur de `ssh_config`, sémantique OpenSSH.
- `tilde-ssh` : client russh, avec connexion, chaîne de sauts, agent, `known_hosts`, authentification, keepalive, reconnexion, forwards et shell. Les interactions passent par des traits (`HostKeyVerifier`, `Prompter`), pour être testables sans UI.
- `tilde-session` : généralisée à des *backends* (PTY ou SSH) qui partagent la même pompe de sortie.

`src-tauri` relie les traits d'interaction à des événements (`ssh://prompt`, `ssh://state`) et à des commandes de réponse. Le front ajoute un dialogue de connexion rapide, les dialogues d'empreinte et d'identifiants, un indicateur d'état par onglet et un panneau de tunnels minimal. Les tests d'intégration tournent contre trois conteneurs OpenSSH (2 bastions + 1 cible) via Docker.

**Tech Stack:** russh 0.64 (`default-features = false`, features `ring`, `rsa`, `flate2`) · tokio · keyring 3 (`windows-native`, `apple-native`, `sync-secret-service`) · glob · hmac + sha1 (known_hosts hachés) · base64 · Docker (Alpine + OpenSSH) pour les tests.

**Spec:** `docs/superpowers/specs/2026-10-23-tilde-design.md` (§4.4, §4.5, §4.10, §6 phase 3). Plans précédents : phases 1 et 2.

## Global Constraints

- Tout ce qui précède reste valable (Tauri 2, crates métier sans Tauri, IPC binaire, aucun secret en clair sur disque ni dans les logs, commits conventionnels + `Co-Authored-By`).
- russh **0.64** avec `default-features = false, features = ["ring", "rsa", "flate2"]`. `aws-lc-rs` est exclu : il exige CMake/NASM sous Windows.
- `ssh_config` : **la première valeur obtenue gagne** ; mots-clés insensibles à la casse ; `IdentityFile`, `LocalForward`, `RemoteForward`, `DynamicForward` et `CertificateFile` sont cumulatifs ; `Include` est relatif à `~/.ssh` et limité à une profondeur de **16** ; `Match exec|canonical|final` produit un diagnostic et ne correspond pas.
- `known_hosts` : `~/.ssh/known_hosts` + `UserKnownHostsFile` ; lecture des entrées hachées `|1|`, de `[host]:port`, des motifs `*`/`?`/`!`, de `@revoked` (refus) et de `@cert-authority` (ignoré, avec diagnostic). Nouvelle entrée ajoutée **en clair** au format OpenSSH (`host` ou `[host]:port` si le port ≠ 22) dans le premier fichier ; empreinte affichée en `SHA256:` base64 sans padding.
- Empreinte modifiée : refus par défaut. Seule une action explicite de l'utilisateur (« Remplacer et continuer ») réécrit la ligne.
- Ordre d'authentification (spec §4.4) : agent → `IdentityFile`(s) → clés par défaut (`id_ed25519`, `id_ecdsa`, `id_rsa`) → keyboard-interactive → mot de passe. `IdentitiesOnly yes` saute l'agent et les clés par défaut.
- Agent : `SSH_AUTH_SOCK` s'il est défini ; sinon, sous Windows, le pipe `\\.\pipe\openssh-ssh-agent` puis Pageant.
- Keepalive : `ServerAliveInterval` / `ServerAliveCountMax` de ssh_config, sinon `settings.ssh.keepaliveIntervalSecs` / `keepaliveCountMax` (15 s / 3).
- Reconnexion (si `settings.ssh.autoReconnect`) : backoff 1, 2, 4, 8, 16, puis 30 s plafonné ; nouvelle tentative illimitée tant que l'onglet est ouvert ; un nouveau shell est ouvert et la ligne `\r\n\x1b[2m── reconnecté ──\x1b[0m\r\n` est injectée dans la sortie.
- Flux SSH : chaque canal russh est **vidé en continu** (ne jamais bloquer la boucle de session). La contre-pression vers le serveur passe par `Handler::adjust_window` : fenêtre de **2 Mio** en temps normal, **32 Kio** tant que la session est en pause côté pompe.
- Secrets : keyring, service `dev.tilde.app`, comptes `ssh-password:{user}@{host}:{port}` et `ssh-passphrase:{chemin absolu de la clé}`. Jamais dans `settings.json`, `workspace.json` ni les logs (les champs secrets ne sont jamais passés à `tracing`).
- `ProxyCommand` : `cmd /C` sous Windows, `sh -c` ailleurs ; tokens `%h %p %r %n %%` ; stderr journalisé et inclus dans l'erreur en cas d'échec.
- Les clés et mots de passe de test (Docker) sont **dédiés aux tests**, rangés sous `tests/docker/` et ne servent nulle part ailleurs.

## Review Focus

1. **`~/.ssh/config` réel tordu** (Include imbriqués et circulaires, `Host *` en tête, `Match` non supportés, guillemets, `=`, tabulations, BOM, CRLF, fichier absent ou illisible) → jamais de crash ; diagnostics avec fichier:ligne ; les hôtes valides restent utilisables. Tests : Task 1 `include_cycle_is_cut`, `crlf_bom_and_tabs`, Task 2 `host_star_first_does_not_override_specific_later_values`.
2. **Serveur injoignable / bastion n°2 qui tombe / mot de passe faux / clé refusée** → message précis (« bastion 2/2 (b2.example) injoignable : délai dépassé », « authentification refusée par user@host — méthodes essayées : agent, ~/.ssh/id_ed25519, mot de passe »), jamais un écran figé. Tests : Task 5 `wrong_password_lists_methods_tried`, Task 7 `unreachable_second_hop_names_the_hop`.
3. **Empreinte modifiée ou révoquée** → connexion refusée tant que l'utilisateur n'a pas choisi ; `@revoked` refusé sans option de contournement. Tests : Task 3 `revoked_key_is_rejected`, Task 5 `changed_host_key_is_refused_by_default`.
4. **`cat` d'un gros fichier distant pendant qu'un autre canal travaille** → mémoire bornée, l'autre canal (shell ou tunnel) reste réactif. Test : Task 8 `remote_flood_does_not_starve_other_channels`.
5. **Coupure réseau (veille du PC, Wi-Fi)** → état « perdu » visible en moins de `interval × countMax`, reconnexion automatique, tunnels rétablis, pas de doublon de session côté Rust. Tests : Task 8 `reconnects_after_server_restart`, Task 9 `forwards_survive_reconnect`.
